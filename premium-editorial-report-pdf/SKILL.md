# Premium Editorial Reports & Decks

Create reports and decks that make one important idea easy to notice and understand on each page or slide. Make the visual design support the argument, not compete with it.

## Select the output mode

Choose the mode that matches how the audience will consume the work. If the user names a format, follow it. Ask one focused question only when the format would materially change the work.

### Editorial Report Mode

Use this mode for detailed reading, review, or reference.

- Default to A4 portrait; follow the requested dimensions or supplied template.
- Use detailed writing, citations, footnotes, methodology, and long-form analysis.
- Deliver the final PDF and an editable source file where possible.

### Editorial Presentation Mode

Use this mode for live presentation, pitching, teaching, executive discussion, or a deck people will scan quickly.

- Default to 16:9 widescreen and editable PowerPoint `.pptx`; follow a requested alternate canvas or presentation platform.
- Provide a presentation PDF only when requested or helpful.
- Use one dominant message per slide, large serif headlines, clean sans-serif supporting text, oversized section numbers, strong hierarchy, generous empty space, relevant photography, simple charts, and large statistics.
- Keep writing short and clear. Put explanation, nuances, evidence detail, and talking points in speaker notes when they do not need to appear on the slide.
- Redesign the content for presenting. Never place report pages unchanged inside slides.

## Start well

1. Read the supplied material and extract the central argument, audience, decision or action requested, strongest evidence, required facts, and missing evidence.
2. Use information already provided. Ask at most one focused question only if its answer would materially change the report, such as the intended reader, brand system, required length, or source material.
3. Flag unsupported claims, incomplete citations, missing data, or uncertainty. Do not manufacture evidence, data, quotations, sources, or photographs.
4. Choose the production route:
   - In Editorial Report Mode, use a fixed layout such as PPTX, HTML/CSS, Figma, or Canva for highly visual reports. Use DOCX first for long flowing text or complex tables, then convert to PDF.
   - In Editorial Presentation Mode, use an editable 16:9 PowerPoint workflow and include speaker notes where needed.
5. Create a page map before building. Give every page one primary job: introduce, explain, compare, prove, humanise, summarise, or recommend.

## Evidence and production handoff

Use the relevant PDF, presentation or document production skill for file creation and export. Use consulting-grade-reports-decks when the argument or evidence base needs development. Keep source data, calculations and citation locations linked to the page map. Do not mistake a generated illustration for documentary photography or evidence; label illustrative material where confusion is possible.

Preserve editability with native text, tables and charts when the production route supports it. Do not flatten a slide into a screenshot and call it editable. Keep required sources and material caveats readable in the deliverable, even when supplementary detail also appears in notes.

## Design system

Apply the default system in [references/design-system.md](references/design-system.md) unless the user supplies a real brand system. Translate the principles to the user's brand. Never imitate another company’s logo, trademark, proprietary template, exact composition, or distinctive branded visual language.

Use this narrative sequence wherever it fits:

**Claim → evidence → visual proof → practical meaning**

Write short analytical headlines that say what the evidence means. Prefer “Professionalised roles are growing twice as fast as democratised roles” over “Job growth analysis.”

## Build an editorial report

1. Make the cover quiet: organisation name or logo, title, subtitle, edition/date, and one relevant image or visual field.
2. Use an executive summary and add contents when the report length warrants it. Select the number of findings from the evidence.
3. Use section openers as pauses in the argument. Add an oversized section number, clear title, and short framing statement.
4. On insight and data pages, present one conclusion at the top. Use no more than two charts per page. Label essential values directly and add a source and methodology note beneath every chart.
5. Use photographs only when they support the point. Prefer real work, people, places, or objects in context over generic staged imagery.
6. Move the final pages from findings to action: what the evidence means, what the reader can do, what may happen next, and where uncertainty remains.
7. Add a legible methodology and sources section covering data sources, time period, definitions, calculation methods, sample, limitations, and citation format when relevant.

## Build an editorial presentation

1. Create a slide map before designing. Convert the report’s argument into a presentation story with a clear opening, evidence, implication, recommendation, and close.
2. Select the slide type that communicates each idea most clearly:
   - Cover slide
   - Executive summary
   - Section divider
   - Big statement slide
   - Large statistic slide
   - Data chart slide
   - Comparison slide
   - Problem and evidence slide
   - Process or framework slide
   - Case study slide
   - Recommendation slide
   - Closing slide
3. Give every slide one dominant message. Write a takeaway headline rather than a topic label. Prefer “Entry-level jobs are starting to demand senior-level judgment” over “AI and Entry-Level Employment.”
4. Use the cover to introduce the subject, audience, and moment. Use executive-summary slides to make the conclusion easy to scan. Use section dividers to reset attention before a new part of the argument.
5. Use a big statement, large statistic, evidence, chart, comparison, or case study slide only when it advances the story. Do not use a slide type simply to make the deck look varied.
6. Put supporting detail in speaker notes when it would make the slide dense: explanation, definitions, sourcing, caveats, transition language, and questions for the audience.
7. End with the decision, recommendation, next action, or final thought the audience should remember.

### Presentation chart rules

- Make each chart communicate one finding that directly supports the slide headline.
- Use direct labels and highlight only the series or values that carry the argument.
- Remove unnecessary gridlines, legends, labels, and visual noise.
- Keep the source readable and put extra methodological detail in speaker notes where appropriate.
- Never use a chart that needs a long verbal explanation before its point is visible.

## Writing and data rules

- Write in plain, research-led English. Keep one main idea per paragraph and explain why each finding matters.
- Avoid vague headings, repeated facts, filler, and conclusions that the evidence cannot support.
- Define specialist terms at first use.
- Use bar charts for comparisons, line charts for time series, scatter plots for relationships, and simple dot plots for rankings. Start bar charts at zero unless a different baseline has a stated analytical reason.
- Use one accent series and greys for supporting context. Avoid 3D charts, rainbow palettes, crowded pie charts, misleading scales, and distant legends.
- Show uncertainty, missing values, and methodological limits plainly.

## Verify before delivery

1. Export the PDF in Editorial Report Mode and render every page to an image. Export the `.pptx` in Editorial Presentation Mode, render every slide to an image, and create a PDF only when requested or helpful.
2. Inspect every page or slide visually for clipping, overlaps, broken characters, text overflow, small fonts, weak alignment, poor line breaks, contrast failures, inconsistent margins or spacing, crowded layouts, tiny or unclear charts, low-resolution images, crowded footnotes, mechanical repetition, and unclear focal points.
3. In Editorial Presentation Mode, check specifically for slides with more than one competing idea and move nonessential detail to speaker notes.
4. Correct material issues and re-export affected pages or slides. Stop once the requested quality checks pass; do not loop for subjective perfection.
5. Check page or slide numbers, contents references, spelling, citations, sources, hyperlinks, chart labels, and file size.
6. Deliver the PDF and editable source in Editorial Report Mode. Deliver the editable `.pptx`, optional PDF, chart/source data, and speaker notes in Editorial Presentation Mode. Include a short note naming assumptions, missing data, or limitations.

Do not say the work has been fully checked until the final PDF or deck has been rendered and inspected page by page or slide by slide. If rendering is unavailable, preserve the authored output, run available structural checks, and state the precise visual-verification limitation. Save final artifacts using the environment’s required storage workflow.
