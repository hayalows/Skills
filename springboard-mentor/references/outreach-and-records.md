# Outreach, follow-up, records and privacy

Use this reference for **explicit outreach requests**, weekly planning, follow-ups, official documentation, and reviews of the mentor's supporting tracker. Do not use a weekly outreach template when the student is already in an active conversation.

## Weekly decision order

1. Read the current PC or Certificate & Degree week guide for outreach focus, Required Actions, official deadlines, current links and programme-specific reminders.
2. Check the authorised roster and prior communication, including the latest student reply and any unanswered mentor message.
3. Put crises, pressing deadlines, blocked student needs and promises already made first.
4. Decide the right channel, timing and whether a meeting is useful. Respect contact hours, weekend constraints and preferences.
5. For first contact or a campaign, draft a message that addresses the actual week's purpose. With goals unknown, one easy, relevant question often works.
6. Review the message for policy accuracy and natural voice. Send only with user authorisation, following AI Use Policy and allowed contact procedures.
7. Document only **confirmed** communication and actions. Schedule agreed follow-ups and keep the commitment.

The mentor's outreach library contains examples, not proof that messages were sent. Don't label a student "unresponsive" if the mentor has not checked the correct channel and recent replies.

## Tracking states that must not collapse

| State | Evidence required |
| --- | --- |
| Draft prepared | Text created or saved, not sent |
| Attempted | Verified contact attempt through authorised channel |
| Sent | User confirms delivery/action, or trusted authorised log shows it |
| Student replied | A new substantive incoming message exists |
| Mentor replied | Verified outgoing reply after that incoming message |
| Follow-up due | Agreed date/next action or documented reminder; not proof contact occurred |
| Meeting offered | An invitation exists |
| Meeting booked | Booking accepted, not attended |
| Meeting completed | Verified attendance |
| Required Action saved | Correct official action saved in the Portal |
| Required Action completed | All official completion requirements met |
| Activity documented | Official Portal record completed |
| Closed | No outstanding student or mentor commitments |

A single student can be "student replied" and still need a mentor response. Do not infer that a message was sent from a completed draft, that a booked meeting happened, or that changing a Google Sheet completes official Portal documentation.

## Mentor Portal and personal tracker

- **Mentor Portal is the official record**. Supporting spreadsheets are personal organisation tools, not substitutes.
- Edit external records only with explicit permission and verified activity. Preserve existing formulas, sheet history and manual notes.
- Before marking a promised follow-up as completed, confirm what was actually done and when.
- Follow the current Handbook for documentation, FERPA verification and contact-time rules.
- Avoid adding speculative tags or medical, financial or family details beyond what the authorised record and policy require.

## Privacy and tool use

Apply Springboard's **current AI Use Policy** and the relevant data handling rules before using AI with student information. Do not copy identifying, confidential or protected student records, prohibited full conversations, restricted recordings, private screenshots or account details into an unauthorised AI workflow. De-identify context appropriately and keep protected work inside approved systems.

Never ask for student passwords, enter accounts as a student, auto-send student messages, auto-transcribe prohibited recordings, or assume that a connected app grants permission to process restricted student data.

**This GitHub repository is public.** Do not put student names, IDs, contact details, private conversation transcripts, internal support tickets, personal roster data, confidential school materials or nonpublic workspace links into this skill. Keep runtime references to private sources in the user's authorised project configuration rather than committed public files.

## Final check

Does the proposed outreach continue an active discussion or accidentally restart it? Is the current guide checked? Are the actions within role and timing rules? Is the student being respected as an individual? Do drafted, sent, replied, documented, recommended and awarded remain separate states? Is an agreed next contact recorded without overstating what happened?
