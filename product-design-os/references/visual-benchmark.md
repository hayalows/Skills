# Visual Craft benchmark protocol

This is a prospective benchmark, not a claim of improved output. Use to compare Product Design OS v2, v3 and Gemini Frontend Design v1.0.0. Freeze exact commit SHAs, model version, inference settings, asset pack, task wording, time and token budget, stack and browser environment. Start each build independently with no access to other variants or their evaluation. Use at least three independent seeds or sessions per condition when supported. Do not give one condition more assets or iteration time.

## Fixed briefs and policy checks

Use identical content, sample data and assets within each brief. The following cases are also a human regression checklist for the skill itself; they are not generated websites.

| Brief | Must protect | Visual opportunity | Reject |
| --- | --- | --- | --- |
| Portable lighting concept store | Clear product concept, real selector, readable mobile | Subject-led composition, coherent product art | Fake sales proof, hidden control |
| Creative studio portfolio | Real work labels and accessible links | Strong type and distinctive case studies | Generic cards or illegible display |
| Event ticket page | Price, date, venue and purchase path | Expressive campaign opening | Hidden fees, invented urgency |
| Local business rules search | Query/results immediately, errors and evidence | Calm type and useful hierarchy | Decorative hero before search |
| Financial dashboard | Comparable values and semantic status | Precise alignment and density | Decorative KPIs or removal of meaningful status |
| Mobile-money checkout | Recipient, amount, fees, pending state, retry safety | Clear reassuring composition | Truncated cost, duplicate payment |
| Editorial news index | Articles, categories and dates immediately | Masthead and editorial rhythm | Prohibiting useful category labels |
| Approved-brand settings repair | Existing components, labels and task behaviour | Minimal scoped refinement | Unrequested restyle, full design workflow for one fix |

## Evaluate

- Save anonymized screenshot sets at 360, 768 and 1280, including scrolled sections at true viewport height, and capture the same states for all variants. Mask model and skill names. Use randomized order and independent reviewers where possible.
- Score visual craft using the shared [visual rubric](visual-craft-engine.md#6-score-visual-craft-separately); score the common [product rubric](quality-rubric.md) separately. Apply the same accessibility, functional and performance checks to all variants, even if a skill omits them.
- Operate the primary task, keyboard path, long content, reduced motion and relevant failure states. Measure contrast, bytes transferred and relevant lab performance with identical profiles. Do not infer field performance from lab data.
- Collect blind pairwise preferences with rationale and reviewer agreement. Publish per-brief, per-seed results, missing evidence, and observed regressions. Do not treat subjective scores as user conversion or statistical significance.
- Adoption criterion: v3 must improve visual craft on expressive briefs without worsening any applicable accessibility, task, trust, performance or state floor on utility and transaction briefs. If evidence is mixed, retain the older behaviour for the affected mode and rerun.

A source-level review can verify that a rule exists and does not conflict with another rule. It cannot establish visual preference, model compliance or a quality improvement. Keep these evidence types separate.
