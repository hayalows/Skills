# Visual identity system reference

Use this file when translating strategy into a visual identity, guidelines, templates, or product-facing components.

## Creative route template

For each route, document:

- route name and one-sentence idea
- strategic truth it expresses
- intended audience feeling
- visual territory and ownable cues
- typography and type hierarchy
- colour palette and usage ratio
- photography or illustration direction
- shapes, patterns, icons, texture, and graphic rhythm
- motion behaviour and reduced-motion alternative
- sample applications
- strengths, risks, and production requirements

A route should be recognisable without the logo. If it relies on a trendy gradient, generic rounded type, or stock illustration style, explain why it will remain ownable.

## Identity specification

### Logo and wordmark

Document primary, reversed, monochrome, small-size, and single-colour versions. Define clear space, minimum size, background control, placement, and prohibited modifications. Show the mark in real contexts, not only on a blank artboard.

### Typography

Define:

- primary display or brand face
- reading or interface face
- fallback stack
- weights and roles
- heading and body hierarchy
- line length, line height, tracking, and casing
- numbers, tables, captions, and data displays
- licensing and language coverage

Test the chosen typefaces in long paragraphs, small mobile text, headlines, numbers, and local language characters. A beautiful display typeface that fails on mobile or lacks the required glyphs is not a complete choice.

State light and dark backgrounds, ratios, contrast results, print conversions, and colour-blind-safe distinctions. Do not use colour as the only signal for status.

### Layout and components

Define a small set of rules that produces variety:

- canvas sizes and responsive breakpoints
- grid, margins, spacing scale, and alignment
- image and text proportions
- buttons, cards, forms, navigation, tables, alerts, and empty states
- content density and hierarchy
- rules for when to use full-bleed, boxed, quiet, or high-energy layouts

The system should support website, social, presentation, email, print, and product UI without forcing every channel to look identical.

### Imagery and graphics

Specify subject, composition, lighting, crop, colour treatment, editing, representation, and prohibited patterns. Avoid generic stock scenes unless the brand has a deliberate reason to use them.

For illustration and icons, define stroke or fill, corner treatment, perspective, scale, animation, and source ownership. If a symbol has local or religious meaning, test it with people who understand that context.

### Motion

Define the brand's movement in verbs such as reveal, settle, snap, drift, or build. Set duration ranges, easing, transitions, loading behaviour, feedback, and a reduced-motion path. Motion should clarify hierarchy or feedback, not make routine work slower.

## Asset and template rules

Use names that reveal the asset's purpose:

`brand_channel_format_variant_version_date`

Example: `hayalows_linkedin_square_dark_v02_2026-08-19`.

Keep editable source files, export files, licences, fonts, and usage notes together. Mark assets as draft, approved, deprecated, or restricted. Never make the team guess which logo or colour file is current.

## System test

Give the same brief to a designer and a non-designer. Check:

- can they find the right assets?
- can they choose the correct type and colour roles?
- can they create a new asset without inventing rules?
- does the result still feel like the same brand?
- does it remain legible on a small screen and in low-bandwidth conditions?

If the answer is no, improve the system or the examples. Adding pages to a guideline document will not fix unclear rules.
