# Master Craft: skill map

This is a **curated routing hint list**, not the authoritative inventory and not a command to load every skill. New skills, renamed folders and updated instructions are automatically detected by the live Git tree; do not reject a skill because it is absent from this map. Read the [freshness protocol](freshness.md) before selecting skills. Paths are relative to `master-craft/` in a complete `hayalows/Skills` checkout. **Before applying a selected skill, read its actual `SKILL.md` and any relevant references.** This map summarizes triggers; the skill file controls its own method. New files may be added after this index was written. Use the current main branch tree or `node master-craft/scripts/inventory.mjs --latest --json` to find them automatically. The map may be revised later for better descriptions, but must never override currently committed skill content. Do not assume a copied skill is installed in the active agent runtime.

**Selection:** usually choose one task-domain owner, `personal-craft` for substantial execution, and zero to three conditional specialists. Use additional skills only where a specific quality gate needs them. A tiny rewrite, read-only audit, or explanation may need only one. Avoid loading competing procedures simultaneously. Distinguish model-invoked vs user-invoked and experimental skills; reading a manual is not the same as invoking a named command.

## Scope and conflict resolution

- `personal-craft` provides the cross-domain working agreement, including its verification and permission rules. The specialized skill supplies domain-specific guidance, not extra authority.
- `product-design-os` governs actual UI/UX/product tasks; do not invoke it for an unrelated coding fix, research report or server deployment.
- `website-ux-audit` is observation-first; a request for audit only does not authorize edits.
- `security-audit` supports source-first defensive examination; full audit mode only when explicitly requested and its isolation requirements can be met. Ordinary implementation still applies proportional security checks through the project quality gates.
- `vercel-deployment-steward` is a conditional release gate for Vercel, not a reason to deploy automatically.
- Matt's experimental or Claude Code-specific skills require supported tools and clear reason. An agent without their prerequisites must explain the limitation or choose a compatible workflow.
- Resolve contradictory methods by system/platform requirements and explicit current user constraints first, followed by project rules, `personal-craft`, domain skill and optional helpers. The root master skill never overrides authorization.
